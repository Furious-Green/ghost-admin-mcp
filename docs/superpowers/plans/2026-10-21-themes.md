# Themes Implementation Plan

> Historical implementation plan. Technical decisions and verification evidence are retained below.

**Goal:** Deliver#10 bounded ZIP transfer and explicit, separate theme activation.
**Architecture:** Reuse canonical base64 and file multipart boundaries from images;
add metadata-only classic ZIP inspector, strict theme schemas/tools, fixed native
upload and bodyless activation routes. No extraction or implicit activation.
**Tech Stack:** Existing TS/Zod/Axios/MCP, Node22 Buffer/crypto, no new dependencies.
**Spec:** `docs/superpowers/specs/2026-10-21-themes-design.md`

## Global Constraints
-54 tools,8 unchanged delete confirmations, `{data,meta?}`.
-ZIP10,485,760 bytes/base6413,981,016 chars;2000 entries/100MiB declared expansion;
  multipart10MiB+8192;response1MiB;30s/0redirects/0retries/proxy:false.
-Upload base64+filename only; activation explicit name only; no paths/URLs/ref/
  MIME/options overrides, local extraction/CRC verification or temp files.
-Upload may overwrite active files/reload site, but never calls activation route.
-No live site changes/private adoption/merge/deploy/publication. Config/license/
  badges/dependencies unchanged;9 advisories remain release/adoption blockers.
-Source reference5.130.0 only; metadata checks are not proof of safe actual
  expansion/theme validity. Test-first implementation, one independent review and pull-request delivery.

## Review Focus
1. ZIP central/local disagreement, overlapping/gapped ranges, descriptors/truncation cannot bypass inspection (Task1).
2. Paths/symlinks/duplicate aliases/declared bomb sizes rejected without extraction or allocations proportional to expanded bytes (Task1).
3. Shared helper extraction preserves image exact limits/errors/wire bytes and never echoes invalid inputs (Tasks1/2).
4. Upload preserves active:true and activation active:false/validation metadata without automatic follow-up (Task2).
5. Bodyless encoded activation, upload cap/timeout/errors and credential policy stay explicit; failures never retry or expose raw server paths (Task3).
